# Results

**Status:** formal campaign complete; results and provenance imported

This directory holds everything about the experimental results *except* the raw data itself.

Every run-generated artifact was deliberately outside the repository for the duration of the formal campaign — raw streams, agent telemetry, per-run manifests, E4 evidence and environment output alike. Formal runs write to `$FAM_RESULTS_DIR`, and the completed dataset is archived as a separate artifact identified by SHA-256.

Two preconditions force this, not one. A clean working tree is required before every formal run, and `HEAD` must stay on the protocol-lock commit ([`experimental-protocol.md` §4](../docs/experimental-protocol.md)) — so neither writing into the tree nor committing between runs is available. The raw JSON Lines volume not belonging in Git blobs is a secondary reason.

Archival copies of manifests, processed datasets and figures arrived here in a post-experiment commit once the campaign was complete ([`experimental-protocol.md` §3](../docs/experimental-protocol.md) Phase 5).

Generated into `$FAM_RESULTS_DIR/environment/` and copied here, because no container writes into the tree |
| `manifests/` | yes | post-experiment import | archival copies, one per formal run, each carrying both raw-stream digests |
| `processed/` | yes | post-experiment import | validated datasets derived from raw data |
| `figures/` | yes | post-experiment import | figures generated by the analysis code |
| `errata/` | yes | post-deposit | dataset errata and the regeneration layer; a copy of what accompanies the deposited archive |
| `raw/` | **no** | never | ignored; a guard against a stray local write, not the intended location |

Nothing under this directory was written during the campaign. `schemas/` and `protocol-lock.json` existed beforehand; the rest arrived afterwards.

The lock is what every formal run checks itself against: a run with `publication_data = true` whose effective parameters differ from it stops rather than producing data under an unrecorded configuration.

Subdirectories appear when they have content. Empty ones are not committed ([`testbed-architecture.md` §31](../docs/testbed-architecture.md)).

The aggregate digest is defined over the inventory rather than over a container:
the sorted `<sha256>  <path>` lines of
`environment/raw-archive-inventory.json`, which depends on what the files contain
and what they are called, not on tar format, compression or timestamps. That
inventory is committed here, so the digest can be recomputed from this repository
against any copy of the raw collection. The collection contains more than one `processed/experiment-summary-*.json`: the analysis was re-run to confirm §63 reproduction, and the copies differ only in `generated_at`. The one committed here is the authoritative summary.

Two files are excluded from the inventory and named in it: the inventory itself and `collection-completion.json`. Both are written after the inventory is computed, so including them would record their previous contents and make the aggregate digest unverifiable against the collection it describes. Skip those two and it recomputes exactly — checked by extracting the archive on a different machine and recomputing from scratch, 433 files, zero per-file mismatches.

**The two campaign identifiers differ, and both are recorded on purpose.** A lock
cannot name the commit that carries it: the artifact has to exist before it can be
committed, so the lock embeds the commit it was generated from, and the campaign
identifier derives from that parameter set. Every execution parameter is identical
between the two, and the executed schedule matches the locked schedule run for run.
This is the single deviation the campaign carries.

## Errata

The deposited dataset carries an errata layer, added beside the archive and not
inside it: `ERRATA.md` and `provenance-authority.json`. A copy is committed here
under [`errata/`](errata). The archive itself is unchanged and its digest is the
one recorded above.

Nine metadata defects are recorded there. None affects a raw observation, a run
validity classification, a numerical result or a figure. Four are worth knowing
before reading an artifact.

**123 formal manifests contradict their own status.** Their `scope_note` asserts
that the run is development data and that `publication_data` is false. It is not:
each carries `publication_data: true` and is formal evidence. The authoritative
field is `publication_data`, which every gate in the pipeline branches on;
`scope_note` is written and never read. The manifests are left unchanged rather
than edited, because correcting archived evidence would make the deposit
something other than what the campaign produced.

**Seven derived artifacts — three from E1, three from E2, one from E4 — cannot
name the revision that produced them.** Their `analysis_code_commit` records a
label such as `task-02-working-tree` instead of a commit. That revision is
unrecoverable and is not guessed at. `protocol_git_commit` is correct in all of
them and identifies the code that produced the raw data. Three further copies
carry the same kind of label, but they are the superseded pre-fix summaries
recorded separately in the errata and are authoritative for nothing.

**The archived E4 summary disclaims its own sessions.**
`processed/e4-validation-latest.json` carries `publication_data: false` and a
development-era note, while all three E4 run manifests carry `true` and that
same file records the verdict it reached over them. It is the only file in the
archive that summarises E4, so it is the one a reader is likely to open first.
The manifests, the transcripts and the revalidation under `errata/reproduced/e4`
agree with each other and against it.

**One interpretive note in the authoritative summary is wrong.**
`e3_summary.environment_drift.note` says runs get faster as the campaign
proceeds; both topologies get slightly slower, and the reported correlations say
so in the same object. The argument the note builds on that direction is
withdrawn in the errata rather than reversed. The drift numbers themselves are
correct and are what the published limitation cites.

## What cannot be reproduced

The E2 recovery comparisons were independently regenerated from the archived
runner and agent streams and matched the archived derived artifacts. E4 was
separately revalidated by running the project validator over the archived
manifests and transcripts; this confirms that the archived inputs still produce
the archived verdict but is not an independent regeneration from raw streams.
The errata layer records both checks under `reproduced/`.

The E1 federation comparison cannot be regenerated from the archived lower-level
streams, and this is a limitation of the evidence model rather than of archive
integrity. Its central observation — that independent reads through both domains
returned the expected 80 experimental events and corresponding membership state
— came from live queries to the two homeservers during the run. Those domain
views were never written to a raw stream, and both homeservers were destroyed
with the formal host. The archived comparison artifacts are the only copy of
those observations, and their digests are pinned in the errata.

This matters because E1 supplies all of C5 and the structural component of C4.
For those claims, the raw streams support the interaction counts and expected
event set, but not the independent two-domain agreement itself.

### Rebuilding the errata layer

Both files under [`errata/`](errata) are generated from the archive, not
written by hand — the first draft was, and it named an aggregate digest that
never existed in it.

```bash
tar xzf fam-formal-raw-<campaign>.tar.gz

python scripts/reproduce_derived.py     --archive fam-formal-results --out errata/reproduced

python scripts/build_errata.py     --archive fam-formal-results     --tarball fam-formal-raw-<campaign>.tar.gz     --reproduced errata/reproduced --out errata
```

The regeneration runs first because the errata cites its result. Neither script
writes into the archive. Given the same archive and the same `--issued` date,
both outputs are byte-identical to the copies committed here.

## Reproduction path

Regenerating the reported tables and figures from the archived raw data:

```bash
# fetch and unpack the dataset: doi.org/10.5281/zenodo.22727175
tar xzf fam-formal-raw-b260ac4df1f524a5.tar.gz
export FAM_RESULTS_DIR=$PWD/fam-formal-results

git checkout protocol-v1.2-lock2
make verify                       # environment and federation readiness
make lock-check                   # lock, commit and tag agree
make audit                        # impossible states, provenance, secrets
make analyse                      # processed datasets and tables
make figures                      # SVG from the processed tables
make decompose                    # round-trip decomposition, explanatory
```

`make decompose` is separate from `make analyse` because it is a
post-collection explanatory analysis, not a primary metric: it re-reads the
archived T0–T3 stamps, checks that the runner's and the agent's clocks form one
consistent timeline, and reports where the round trip is spent and how often the
agent handler takes a new request inside the measurement window. It changes no
frozen parameter and no acceptance criterion. Two properties of its output are
worth stating before reading it:

- **The component percentiles do not sum to the total.** Each is an independent
  order statistic over its own sample. The residual is reported as
  `p50_additivity_shortfall_ms` rather than left for the reader to discover.
- **The service interval is bounded by the frozen measurement window**, the same
  60 s that defines observed throughput, and reduced per run before being
  reduced across runs — so it is comparable with the throughput plateau it is
  meant to explain, and warm-up and drain contribute nothing.

`make analyse` and `make figures` read only the raw collection and the processed
tables respectively, so the chain from evidence to figure is:

```text
raw -> processed -> figure script -> SVG
```

No number in any figure is written by hand; each is read from
`processed/e3-tables/*.csv`.

### Running this without Docker

The container matters for running the testbed, not for reading its output, and
the numerical core in `fam.analysis.e3` uses only the Python standard library.
The entry points divide on one line:

| Needs nothing installed | Needs `requirements.txt` |
|---|---|
| `verify_digests.py` — per-file digests against the manifests | `analyse.py` — the processed datasets and tables |
| `final_audit.py` — the 23 integrity checks | `protocol_lock.py validate` — the lock against its schema |
| `figures.py` — SVG from the processed tables | |
| `decompose.py` — the round-trip decomposition | |

So the archive can be verified, audited and its figures redrawn with a bare
interpreter. The two on the right validate against the tracked JSON Schemas
and therefore need `jsonschema`:

```bash
pip install -r requirements.txt      # or just: pip install jsonschema==4.23.0
PYTHONPATH=src python scripts/analyse.py
```

Both are **fail-closed**. If the library is absent or a schema file is missing,
the run stops before reading any record — `analyse.py` with
`FAIL (dependency)` — and says which of the two it was. Neither degrades to a
weaker check: "could not validate" and "validated, found a problem" are
different statements and are never merged.

Every reported statistic was recomputed this way — from a clean clone and a
freshly unpacked archive, on a different interpreter and operating system
(Python 3.14 on Windows, against the frozen Python 3.12 on Linux) — and
reproduced exactly: all six latency percentiles, three latency ratios and two
throughput ratios, each with its bootstrap interval, to the last recorded
digit. The four `e3-tables/*.csv` come back byte-identical to the copies
committed here, and the regenerated summary differs from the committed one in
`generated_at` and `analysis_code_commit` and in no analytical field.

One caution when re-running against an extracted archive: `analyse.py` writes a
new `processed/experiment-summary-<stamp>.json` each time. Point
`FAM_RESULTS_DIR` at a copy, or the archive gains a summary the errata does not
list.

## Integrity rules

- Raw outputs are immutable once written ([`experimental-protocol.md` §34](../docs/experimental-protocol.md)). Analysis code never overwrites them.
- Only runs executed against a locked protocol version are publication data. Pilot output carries `publication_data = false` and is never merged in.
- Every excluded formal run has a documented reason in [`evidence-matrix.md` §7](../docs/evidence-matrix.md), classified as an invalid run or a valid experimental failure. Valid failures stay in the dataset.
- Processed results retain references to their source experiment, run, raw file, `analysis_spec_version` and `analysis_code_commit`.
