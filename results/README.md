# Results

**Status:** no data collected

This directory holds everything about the experimental results *except* the raw data itself.

Every run-generated artifact is deliberately outside the repository for the duration of the formal campaign — raw streams, agent telemetry, per-run manifests, E4 evidence and environment output alike. Formal runs write to `$FAM_RESULTS_DIR`, and the completed dataset is archived as a separate artifact identified by SHA-256.

Two preconditions force this, not one. A clean working tree is required before every formal run, and `HEAD` must stay on the protocol-lock commit ([`experimental-protocol.md` §4](../docs/experimental-protocol.md)) — so neither writing into the tree nor committing between runs is available. The raw JSON Lines volume not belonging in Git blobs is a secondary reason.

Archival copies of manifests, processed datasets and figures arrive here in a single post-experiment commit once the campaign is complete ([`experimental-protocol.md` §3](../docs/experimental-protocol.md) Phase 5).

## What lives here

| Path | Tracked | When it appears | Contents |
|---|---|---|---|
| `README.md` | yes | before the campaign | this file — the artifact record below |
| `schemas/` | yes | before the campaign | versioned result and manifest schemas |
| `protocol-lock.json` | yes | at protocol lock | the formal lock — implementation commit, environment, frozen parameters and the complete E3 run schedule ([`experimental-protocol.md` §46](../docs/experimental-protocol.md)). Generated into `$FAM_RESULTS_DIR/environment/` and copied here, because no container writes into the tree |
| `manifests/` | yes | post-experiment import | archival copies, one per formal run, each carrying both raw-stream digests |
| `processed/` | yes | post-experiment import | validated datasets derived from raw data |
| `figures/` | yes | post-experiment import | figures generated by the analysis code |
| `raw/` | **no** | never | ignored; a guard against a stray local write, not the intended location |

Nothing under this directory is written during the campaign. `schemas/` and `protocol-lock.json` exist beforehand; the rest arrives afterwards.

The lock is what every formal run checks itself against: a run with `publication_data = true` whose effective parameters differ from it stops rather than producing data under an unrecorded configuration.

Subdirectories appear when they have content. Empty ones are not committed ([`testbed-architecture.md` §31](../docs/testbed-architecture.md)).

The aggregate digest is defined over the inventory rather than over a container:
the sorted `<sha256>  <path>` lines of
`environment/raw-archive-inventory.json`, which depends on what the files contain
and what they are called, not on tar format, compression or timestamps. That
inventory is committed here, so the digest can be recomputed from this repository
against any copy of the raw collection. The collection contains more than one `processed/experiment-summary-*.json`: the analysis was re-run to confirm §63 reproduction, and the copies differ only in `generated_at`. The one committed here is the authoritative summary.

Two files are excluded from the inventory and named in it: the inventory itself and `collection-completion.json`. Both are written after the inventory is computed, so including them would record their previous contents and make the aggregate digest unverifiable against the collection it describes. Skip those two and it recomputes exactly — checked by extracting the archive on a different machine and recomputing from scratch, 433 files, zero per-file mismatches.

**The two campaign identifiers differ, and both are recorded on purpose.** A lock
cannot name the commit that carries it: the artifact has to exist before it can be
committed, so the lock embeds the commit it was generated from, and the campaign
identifier derives from that parameter set. Every execution parameter is identical
between the two, and the executed schedule matches the locked schedule run for run.
This is the single deviation the campaign carries.

## Reproduction path

Regenerating the reported tables and figures from the archived raw data:

```bash
export FAM_RESULTS_DIR=/path/to/the/raw/collection

git checkout protocol-v1.2-lock2
make verify                       # environment and federation readiness
make lock-check                   # lock, commit and tag agree
make audit                        # impossible states, provenance, secrets
make analyse                      # processed datasets and tables
make figures                      # SVG from the processed tables
```

`make analyse` and `make figures` read only the raw collection and the processed
tables respectively, so the chain from evidence to figure is:

```text
raw -> processed -> figure script -> SVG
```

No number in any figure is written by hand; each is read from
`processed/e3-tables/*.csv`.

## Integrity rules

- Raw outputs are immutable once written ([`experimental-protocol.md` §34](../docs/experimental-protocol.md)). Analysis code never overwrites them.
- Only runs executed against a locked protocol version are publication data. Pilot output carries `publication_data = false` and is never merged in.
- Every excluded formal run has a documented reason in [`evidence-matrix.md` §7](../docs/evidence-matrix.md), classified as an invalid run or a valid experimental failure. Valid failures stay in the dataset.
- Processed results retain references to their source experiment, run, raw file, `analysis_spec_version` and `analysis_code_commit`.
